# Từ điển thuật ngữ MealPlaning (Glossary)

> Tài liệu tra cứu nhanh các từ tiếng Anh / thuật ngữ kỹ thuật xuất hiện trong project MealPlaning.
> Mỗi mục: **Từ tiếng Anh** — *Tiếng Việt* — Giải thích ngắn gọn.
> Bổ sung khi gặp từ mới.

---

## A. Quy trình & Phương pháp luận (Methodology)

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **Hypothesis** | Giả thuyết | Phỏng đoán ban đầu chưa chắc đúng, phải đem đi kiểm chứng |
| **Validation** | Kiểm chứng / Xác minh | Đem giả thuyết đối chiếu với bằng chứng |
| **Evidence** | Bằng chứng | Dữ liệu thật từ nguồn (web, doc, code) |
| **Confidence** | Độ tin cậy | Mức tin tưởng vào kết luận: High (cao) / Medium (trung bình) / Low (thấp) |
| **Confirmed** | Đã xác nhận đúng | Giả thuyết được dữ liệu chứng minh đúng |
| **Partial confirm** | Đúng một phần | Giả thuyết đúng nửa, sai nửa |
| **Audit** | Rà soát / Soát xét | Tự kiểm tra lại chất lượng work |
| **Self-audit** | Tự rà soát | Tự kiểm tra mình, không đợi ai chỉ ra |
| **Adversarial review** | Tư duy phản biện | Cố tình tìm điểm yếu trong work của chính mình |
| **Cynical pass** | Soát kỹ với thái độ nghi ngờ | Đọc lại với tâm thế "có gì sai?" |
| **Gap** | Lỗ hổng / Thiếu sót | Chỗ thiếu thông tin hoặc thiếu evidence |
| **Root cause** | Nguyên nhân gốc rễ | Lý do thực sự của vấn đề (không phải triệu chứng) |
| **Trade-off** | Đánh đổi | Được cái này phải mất cái kia |
| **Scope** | Phạm vi | Giới hạn công việc làm/không làm |
| **In scope / Out of scope** | Trong phạm vi / Ngoài phạm vi | Có làm / Không làm |
| **Assumption** | Giả định | Điều mình tin là đúng nhưng chưa verify |
| **Constraint** | Ràng buộc | Giới hạn bắt buộc (kỹ thuật, thời gian, ngân sách) |
| **Deliverable** | Sản phẩm bàn giao | Output cuối cùng cần nộp |
| **Definition of Done (DoD)** | Tiêu chí hoàn thành | Khi nào coi là xong |

## B. Research / Nghiên cứu

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **Spot-check** | Khảo sát sơ / Kiểm tra nhanh | Research mỗi đối tượng 1-2 query |
| **Deep dive** | Nghiên cứu sâu | Research kỹ với nhiều query, nhiều nguồn |
| **Frequency** | Tần suất | Số lần xuất hiện / tổng số mẫu |
| **Universal** | Phổ biến toàn bộ | 100% mẫu đều có |
| **Common / Rare** | Phổ biến / Hiếm | Mức độ xuất hiện |
| **Wave** | Đợt research | Wave 1, 2, 3 = đợt 1, 2, 3 |
| **Cross-app comparison** | So sánh chéo nhiều app | Đối chiếu pattern giữa các app |

## C. Thị trường (Market & Business)

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **CAGR** | Tốc độ tăng trưởng kép hàng năm | Compound Annual Growth Rate — % thị trường tăng mỗi năm |
| **Market share** | Thị phần | % thị trường của 1 player |
| **Incumbent** | Player đã có sẵn / Tay chơi cũ | Đối thủ đã chiếm lĩnh thị trường |
| **Differentiator** | Điểm khác biệt | Tính năng app mình có mà đối thủ không có |
| **Saturated market** | Thị trường bão hòa | Thị trường đã đầy, ít cơ hội mới |
| **Growth stage** | Giai đoạn tăng trưởng | Thị trường còn dư địa lớn |
| **Niche** | Ngách | Phân khúc nhỏ, chuyên biệt |
| **Segment** | Phân khúc | Nhóm khách hàng / sản phẩm theo tiêu chí |
| **Positioning** | Định vị | Cách app tự xác định vị trí trên thị trường |
| **Value proposition** | Giá trị cốt lõi mang lại | Lý do user chọn app mình |
| **B2B / B2C** | Doanh nghiệp / Người dùng cuối | Business-to-Business / Business-to-Consumer |
| **Freemium** | Miễn phí + có gói trả phí | Model dùng miễn phí, trả phí mở khóa tính năng |
| **Subscription** | Đăng ký trả phí định kỳ | Trả tiền hàng tháng/năm |
| **Churn rate** | Tỷ lệ rời bỏ | % user bỏ app trong khoảng thời gian |
| **Retention** | Tỷ lệ giữ chân | % user còn dùng app sau X ngày |
| **DAU / MAU / WAU** | Active hàng ngày / tháng / tuần | Daily/Monthly/Weekly Active Users |

## D. UX & Thiết kế

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **UX** | Trải nghiệm người dùng | User Experience |
| **UI** | Giao diện | User Interface |
| **Pattern** | Mẫu thiết kế | Cách làm chuẩn được nhiều app dùng |
| **Anti-pattern** | Mẫu thiết kế tệ / Cách làm sai | Pattern NÊN tránh vì gây hại |
| **De-facto standard** | Chuẩn ngầm thị trường | Cả ngành công nhận dù không có tổ chức quy định |
| **Onboarding** | Hướng dẫn ban đầu | Màn hình đầu tiên khi user mới cài |
| **First-run** | Lần chạy đầu | Lần user mở app đầu tiên |
| **Empty state** | Trạng thái rỗng | UI khi chưa có data |
| **Wizard** | Trình hướng dẫn từng bước | Chuỗi màn hình hỏi user từng bước |
| **Progressive disclosure** | Lộ dần dần | Hiển thị tính năng khi user cần, không hỏi tất cả 1 lúc |
| **CTA** | Nút kêu gọi hành động | Call-To-Action — VD nút "Đăng ký ngay" |
| **FAB** | Nút hành động chính nổi | Floating Action Button — nút tròn nổi góc dưới |
| **Toast** | Thông báo nhỏ tạm thời | Notification trượt lên 2-5s rồi tự tắt |
| **Modal** | Cửa sổ pop-up chặn thao tác | Hộp thoại che màn hình, phải xử lý mới đóng |
| **Bottom sheet** | Tấm trượt từ dưới lên | Panel xuất hiện từ đáy màn hình |
| **Streak** | Chuỗi ngày liên tiếp | Đếm số ngày user dùng app liên tục (Duolingo style) |
| **Gamification** | Yếu tố trò chơi hóa | Dùng điểm, badge, bảng xếp hạng để khuyến khích |
| **Microcopy** | Câu chữ nhỏ trong UI | Tooltip, label, error message |
| **Mental model** | Mô hình tư duy của user | Cách user hình dung app hoạt động |
| **Affordance** | Gợi ý hành vi | Thiết kế ngụ ý "nút này bấm được" |
| **Hierarchy** | Phân cấp | Thứ tự ưu tiên thông tin trên màn hình |
| **Accessibility (a11y)** | Khả năng tiếp cận | Hỗ trợ user khuyết tật (đọc màn hình, font lớn…) |
| **Wireframe** | Khung dây | Bản phác thảo UI đơn giản |
| **Mockup** | Bản giả lập | Bản thiết kế gần thật |
| **Prototype** | Bản chạy thử | Bản mockup có thể tương tác |
| **Design system** | Hệ thống thiết kế | Bộ component + rule UI nhất quán |

## E. Dữ liệu & Tracking (Cụ thể project)

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **TDEE** | Tổng năng lượng tiêu hao hàng ngày | Total Daily Energy Expenditure — số calo cơ thể đốt mỗi ngày |
| **BMR** | Tỷ lệ trao đổi chất cơ bản | Basal Metabolic Rate — calo đốt khi nghỉ ngơi |
| **Macro** | Đa lượng | Protein, Carbs, Fat (3 nhóm chất chính) |
| **Micronutrient** | Vi lượng | Vitamin, khoáng chất |
| **Snapshot (SNAP)** | Chụp ảnh / Đóng băng giá trị | Lưu giá trị tại thời điểm đó, sau này không đổi |
| **Realtime (RT)** | Thời gian thực / Tính lại liền | Luôn dùng giá trị mới nhất |
| **Hybrid** | Lai / Kết hợp | Vừa SNAP vừa RT tùy trường hợp |
| **Canonical** | Chuẩn / Gốc | Dạng chuẩn (VD canonical = 100g/100ml) |
| **Logging** | Ghi nhật ký | User nhập món đã ăn |
| **Diary** | Nhật ký | Danh sách món đã ăn theo ngày |
| **Plan / Plan-ahead** | Kế hoạch trước | Đặt trước món sẽ ăn ngày mai/tuần sau |
| **Meal slot** | Khung bữa | Sáng / Trưa / Chiều / Phụ |
| **Quick add** | Thêm nhanh | Log không qua search, chỉ nhập calo |
| **Copy from yesterday** | Sao chép từ hôm qua | Lặp lại bữa hôm trước |

## F. Kỹ thuật (Technical)

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **Backend** | Phía máy chủ | Code chạy server |
| **Frontend** | Phía giao diện | Code chạy trên app/web |
| **API** | Giao diện lập trình | Cách 2 phần mềm "nói chuyện" với nhau |
| **REST / GraphQL** | Kiểu API | 2 chuẩn API phổ biến |
| **Schema** | Cấu trúc dữ liệu | Định nghĩa các cột/field trong DB |
| **Migration** | Di chuyển schema | Thay đổi cấu trúc DB an toàn |
| **CHECK constraint** | Ràng buộc kiểm tra | Quy tắc DB tự enforce dữ liệu hợp lệ |
| **PK / FK** | Khóa chính / Khóa ngoại | Primary Key / Foreign Key |
| **PRD** | Tài liệu yêu cầu sản phẩm | Product Requirements Document |
| **MVP** | Sản phẩm tối thiểu khả dụng | Minimum Viable Product |
| **CI/CD** | Tích hợp / Triển khai liên tục | Continuous Integration / Deployment |
| **Guard** | Cổng kiểm tra tự động | Script CI chặn merge nếu vi phạm rule |
| **Lint** | Soát lỗi cú pháp | Tool check code style |
| **Refactor** | Tái cấu trúc | Sửa code cho sạch, không đổi behavior |
| **Tech debt** | Nợ kỹ thuật | Code "vay" sửa nhanh, sau phải trả bằng refactor |
| **Hotfix** | Sửa lỗi khẩn | Fix nhanh chạy production |
| **Rollback** | Quay lại bản cũ | Hủy thay đổi vừa deploy |
| **Snapshot (DB)** | Bản chụp DB | Backup DB tại 1 thời điểm |

## G. BMAD Method (Phương pháp BMAD)

| Tiếng Anh | Tiếng Việt | Giải thích |
|---|---|---|
| **BMAD** | (Tên phương pháp) | Khung quy trình AI-assisted: Business → Architect → Develop |
| **Persona** | Vai diễn | AI đóng vai chuyên gia (Mary Analyst, Sally UX, James Dev…) |
| **Activate** | Kích hoạt persona | AI bắt đầu đóng vai |
| **Skill** | Kỹ năng AI | Một workflow đóng gói (template + checklist) |
| **Workflow** | Quy trình | Chuỗi bước thực hiện task |
| **Step** | Bước | Một bước trong workflow |
| **Pipeline** | Dòng chảy công việc | Chuỗi step từ đầu đến cuối |
| **Phase** | Giai đoạn | Mốc lớn trong project (Phase 1, 2, 3…) |
| **Artifact** | Tài liệu sản phẩm | File output (PRD, architecture, story…) |
| **Story** | Câu chuyện user | Yêu cầu nhỏ "Là [user] tôi muốn [X] để [Y]" |
| **Epic** | Chùm story lớn | Nhóm nhiều story liên quan |
| **Sprint** | Chu kỳ làm việc ngắn | 1-2 tuần làm việc |

## Quy tắc giao tiếp với Khánh

1. **Nói chuyện trực tiếp** → Em dùng **100% tiếng Việt**
2. **Bắt buộc dùng từ tiếng Anh** (vì là thuật ngữ chuẩn ngành) → Em sẽ **giải thích ngay sau từ đó** lần đầu xuất hiện trong cuộc trò chuyện
   - VD: "Em chạy *audit* (rà soát chất lượng) cho Step 3"
3. **Tài liệu kỹ thuật trong `_bmad-output/` và `docs/`** → Vẫn giữ thuật ngữ tiếng Anh để dev/designer tham khảo, nhưng **bổ sung giải thích inline** khi term mới hoặc đặc biệt
4. **File này** (`docs/glossary.md`) là **nguồn chuẩn duy nhất** — anh tra cứu khi cần
5. **Bổ sung** khi em hoặc anh phát hiện từ mới chưa có trong glossary
